# 设计说明

## 要解决的问题

聊天角色长期跑下去，会同时被三件事侵蚀：

1. **上下文上限**——聊得越久，越要截断，最早的人设先被挤掉；
2. **多次压缩/摘要**——每压一次，语气细节、称呼习惯、答应过的事都在损耗，模型的默认腔调会一点点回流；
3. **换会话/迁移**——会话状态一丢，角色就像失忆重开，前后不是同一个人。

这个库不试图让上下文永不丢，而是把**不能丢的东西**从上下文里外置成有预算上限的文件，每次唤醒按固定预算重新注入。预算固定，就不随聊天变长而变贵。

## 四层记忆

| 层 | 回答的问题 | 存储 | 默认预算 | 生命周期 |
|---|---|---|---|---|
| 人格内核 | 她是谁、怎么说话、不能做什么 | `persona-core/<角色>.md` | 600 字 | 长期，人工/半自动维护 |
| 长期事实 | 对方是谁（名字、喜好、雷点、关系、计划） | `state/<角色>/facts.jsonl` | 300 字 / 6 条 | 长期，去重覆盖 |
| 事件日记 | 发生过什么、答应过什么 | `state/<角色>/diary.jsonl` | 400 字 | 长期，1MB 轮转 |
| 交接单 | 上一个会话聊到哪了 | `state/<角色>/handoff.json` | 700 字 | **一次性**，读过即失效 |

四层互不覆盖：交接单不会删除事实，事实不会改写内核。

## 为什么内核要单独存

完整角色卡通常 5k~15k 字，是为了「像」；内核 300~600 字，是为了「不掉」。两者职责不同：

- 角色卡进常规人设提示词（每轮都在）；
- 内核是一个**压缩后仍必须保留**的最小集合，单独成文件、单独预算、单独版本号。

内核带 `draft: true` 时整段不注入——上线/回滚都是改一行 front matter。

内核的 `personaHash`（正文 sha256 前 12 位）会随每轮日志输出，方便发现「注入的东西什么时候变了」。

## 为什么一个角色一个文件

文件即边界。多角色共存时：

- `persona-core/<角色>.md` 按角色名精确匹配，缺文件就静默跳过（不报错、不串到别人）；
- `state/<角色>/` 决定记忆归属，一个角色的日记不会被另一个角色看见；
- 预算写在各自 front matter 的 `budgetChars` 里，互不影响。

新增角色 = 加两个文件，不改代码。

## 会话维度

同一个角色可能同时活在多个会话窗口里（不同房间、不同对话线程）。记忆必须按窗口分开，否则 A 窗口的事会漏到 B 窗口。

实现方式是**每条记录带 `conv`**（会话标识，宿主自定义字符串，建议 `<channel>:<id>` 形式），而不是按窗口拆文件：

- 一个角色仍然只有一份 JSONL，便于整体备份/迁移；
- 注入时按 `conv` 过滤，取「本窗口 + 无 conv 的通用条目」；
- 无 `conv` 的旧数据对所有窗口可见，升级不会丢记忆。

## 注入顺序与预算

唤醒时一次拼装，顺序固定（越靠前越不容丢失）：

```
人格内核 → 长期事实 → 事件日记（最近 N 条 + 相关 M 条）→ 交接单
```

每块独立按字符预算截断，超了按条目/行整块丢弃，不拦腰砍。合计约 1300 字（≈1k token），不随历史增长。

## 事实的提炼

`extractFacts(text)` 用句式规则从**对方发来的**文字里抽取事实候选（自我介绍、口味、宠物、关系、计划等 11 类），不调用模型：

- 只记对方说的，不记 AI 自己的话——避免「自己给自己编设定」；
- `factKey()` 归一化（去标点空白、小写）后去重，后写的覆盖旧的；
- 上限 200 条，超出淘汰最旧。

规则法的取舍：够快、可解释、零成本；代价是覆盖面有限、依赖中文表达习惯，长句和隐含表达会漏。需要更高召回时可以在宿主侧换成模型抽取，接口不变（`appendFact`）。

## 检索

日记/事实的「相关条目」用 `queryTerms()`（中文二元组 + 英文词）配 `searchDiary()` / `searchFacts()` 做关键词命中计分。

不引入向量检索，理由：零依赖、可离线、结果可解释；代价是近义改写召回弱。数据量（几千行）下关键词够用。

## 交接单只读一次

交接单是一次性的开场白，不是长期记忆。标记 `usedAt` 的时机是**投递成功之后**，而不是生成之后：

- 生成失败/投递失败不会浪费；
- 读过一次不再注入，避免每轮重复占预算，也避免它变成新的噪音；
- 交接单不删除任何数据，只读不写。

## 非目标

- 不做数据库：所有数据是 JSONL / Markdown / JSON，`cat`、`grep`、`rsync` 都能处理；
- 不做自动换会话：什么时候换由人决定，库只负责生成交接单和在轮数到阈值时提醒；
- 不做平台绑定：没有 QQ / 微信 / Discord 的 SDK 依赖，宿主自己决定何时读写；
- 不做加密：数据是明文，隐私边界在文件系统权限和宿主的访问控制上。
